SUPER ADMIN EXCLUSIVE FEATURES (IN ADDITION TO ADMIN ACCESS)
================================================================================

These endpoints are ONLY available to super_admin role:

Routes: routes/superadmin.route.ts (Base: /api/v1/superadmin/)

1. GET /admins
   - Get all admin and super_admin users

2. POST /admins/add
   - Create new admin account
   - Request: { name, email, password? (optional) }
   - Password auto-generated if not provided

3. DELETE /admins/{adminId}
   - Remove admin account

4. GET /activity-logs
   - View all admin activity logs with filtering
   - Query params: adminId, action, startDate, endDate, limit, page

5. GET /activity-logs/summary
   - Get summary statistics of admin activities
   - Query params: startDate, endDate (optional)

6. GET /activity-logs/{adminId}
   - View specific admin's complete activity history
   - Query params: limit, page

================================================================================
AUTHORIZATION PATTERN - OLD VS NEW
================================================================================

OLD PATTERN (Before Update):
authorizeRoles("admin")

NEW PATTERN (After Update):
authorizeRoles("admin", "super_admin")

This ensures any endpoint that was previously admin-only is now also available
to super_admin, while maintaining the same security constraints and requiring
authentication.

MIDDLEWARE VALIDATION
================================================================================

The authorization middleware (auth.ts) validates that:
1. User is authenticated (has valid JWT token)
2. User's role is in the allowed roles list
3. If no matching role, access is denied with 403 Forbidden

Updated routes use:
authorizeRoles("admin", "super_admin")

This will allow EITHER admin OR super_admin role to access the endpoint.
